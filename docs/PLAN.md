# План: STB Editor (рабочее имя) — замена Creation Kit для Skyrim SE

Разбор концепта и CK, обоснование выбора — [ANALYSIS.md](ANALYSIS.md).
Решения, помеченные ❓, ждут ответа (вопросы — в конце).

## 1. Цель

Отдельная программа для Windows, которая открывает load order (MO2-профиль или чистый `Data`)
за секунды, а не минуты, и даёт основной функционал CK: расстановку объектов в 3D, правку
ячеек и миров, ландшафта, навмеша, любых записей, скриптов и их свойств (без компиляции).
Плюс простая правка NIF. Плагины ESP / ESM / ESL, header 1.70 и 1.71.

Не делаем: компиляцию Papyrus, LOD-генерацию (xLODGen/DynDOLOD), моделирование геометрии.

### Ключевые решения

1. **Данные — Mutagen.** Типизированы все записи Skyrim SE, ESL/ESM, localized strings, мастера,
   link cache. Свой парсер TES4 не пишем (кроме «сырого» слоя для хирургической записи).
2. **Хирургическая запись.** Плагин = исходный файл + набор изменённых записей. При сохранении
   нетронутые записи и группы копируются байтами; меняются только изменённые; пересчёт размеров
   GRUP, счётчика записей и NextObjectID в HEDR. Проверка round-trip, бэкап, атомарная замена,
   журнал. Это защищает от нормализации/потерь Mutagen (ловили потерю строк).
3. **Модель правки как в CK:** одно активное изменяемое «документ-плагин», остальные — только
   чтение. Правка записи из мастера = override в активном плагине. ❓ Нужно ли править несколько
   плагинов сразу (как xEdit).
4. **Свой VFS** вместо запуска через MO2: читаем `modlist.txt`/`plugins.txt`/`loadorder.txt`
   профиля (код SkyrimBridge), строим приоритеты loose-файлов и BSA. Сохраняем прямо в папку
   мода, где лежит плагин (или в выбранный мод) — никакой «публикации после выхода».
5. **NIF:** генератор C#-классов из `nif.xml` → чтение/запись всех блоков SSE с сохранением
   неизвестного. На этом стоят и рендер, и NIF-редактор.
6. **Рендер D3D11** (как игра, проще отлаживать, BC-текстуры напрямую): BSLightingShader-приближение
   (diffuse/normal/spec/glow/env/skin/hair tint), alpha test/blend, ландшафт с блендом слоёв и vertex
   color, вода-плоскость, дальний LOD из `.btr/.bto`, маркеры, ID-буфер для пикинга, обводка.
   ❓ Уровень похожести на игру.
7. **Undo/redo** — команды над документом (не снимки), группировка, история в панели.
8. **Фоновые задачи** (индекс, загрузка ячеек, ассеты) — не блокируют UI; отмена и прогресс.

## 4. Этапы

Каждый этап заканчивается рабочей сборкой, которую можно проверить на сборке STB.
Текущее состояние по этапам — таблица «Состояние» в [README](../README.md).

### Этап 0 — каркас и данные (только чтение)
- Решение, проекты, логирование, настройки, крэш-репорт с минидампом.
- Load order: MO2-профиль / чистый `Data`; FormID ↔ FormKey с ESL; ошибки отдельных плагинов
  не ломают индексы остальных (как в SkyrimBridge).
- VFS: loose + BSA с приоритетами; DDS, PEX, `.STRINGS`.
- Индекс SQLite с кэшем по отпечатку файлов; поиск по EditorID/имени/FormID/типу.
- Object Window + generic Property Grid (строится по схеме Mutagen) — **просмотр** любой записи,
  все override'ы и победитель.
- **Проверка:** вся сборка STB открывается < 15 с с тёплым кэшем; запись из `STB.esp` совпадает
  с `sse_get_record`.

### Этап 1 — 3D-просмотр
- NIF-кодген, загрузка мешей/текстур, кэш GPU-ресурсов.
- Интерьер: рефы, свет ячейки, маркеры (свет, звук, двери, room/portal/occlusion, primitive).
- Экстерьер: ландшафт (LAND), вода, стриминг ячеек вокруг камеры, дальний LOD.
- Камера как в CK + WASD-полёт, Cell View, переход к рефу, пикинг, обводка.
- **Проверка:** Вайтран, Бликфолл, любая ячейка STB открываются без падений, FPS ≥ 60.

### Этап 2 — расстановка и сохранение (MVP «лучше CK»)
- Гизмо move/rotate/scale в локальных/мировых осях, snap к гриду/углу, snap к поверхности,
  drop to ground, мультивыбор, дубль, копировать/вставить между ячейками, скрыть/заморозить.
- Создание рефа drag&drop из Object Window; безопасное удаление ванильных рефов.
- Свойства рефа: linked refs, enable parent, ownership, lock, teleport (пары дверей с маркерами),
  primitive-размеры, свет (XLIG), emittance, scale, persistent/initially disabled.
- Перенос рефа между ячейками при пересечении границы; persistent-ячейка мира.
- Активный плагин: ESP/ESM/ESL, мастера (добавление/сортировка), header 1.70/1.71, ESL-диапазон.
- Undo/redo, автосохранение, журнал восстановления, хирургическая запись, бэкап.
- **Проверка:** сохранение без правок даёт байт-в-байт тот же файл; правки видны в игре.

### Этап 3 — записи, скрипты, условия
- Редакторы записей: generic для всех + специализированные для частых (STAT/MSTT/FURN/ACTI/CONT/
  DOOR/LIGH/MISC/WEAP/ARMO/ALCH/BOOK/LVLI/LVLN/NPC_/SPEL/MGEF/ENCH/PERK/KYWD/FLST/GLOB…) ❓ приоритет.
- Создание/дубль/переименование записей, Use Info, «найти и заменить» ссылки, массовые правки.
- VMAD: прикрепить скрипт, свойства из `.pex` (тип, массив, объект + алиас), авто-заполнение по
  EditorID как в CK; фрагменты — сохраняем как есть, показываем.
- Редактор условий (CTDA): все функции с типами параметров, проверка.
- Проверка ошибок (как CK «check errors» + xEdit «check for errors»), ITM/UDR очистка.

### Этап 4 — ячейки, миры, ландшафт
- Создание интерьерных и внешних ячеек, мира; освещение ячейки, lighting template, imagespace,
  water, acoustic space, encounter zone, location, регионы.
- Ландшафт: кисти высот (raise/lower/flatten/smooth/noise), текстурные слои с ограничением слоёв
  на квадрант, vertex color, вода ячейки; стыковка соседних ячеек.

### Этап 5 — навмеш
- Навмеш: показ (флаги, edge links, cover, door), правка вершин/треугольников (добавить, удалить,
  сварить, разрезать, флаги), finalize (связи между ячейками, двери, NAVI).
- Генерация (Recast) — позже, по запросу.

### Этап 6 — live-link и большие системы
- SKSE-плагин: камера игры ↔ камера редактора, «показать в игре», горячее применение
  перемещений/новых рефов, телепорт.
- Квесты (алиасы, стадии, цели), диалоги (ветки, топики, инфо, сцены), AI-пакеты.
- Опционально: экспорт facegen NPC.

## 5. Тесты и качество

- Round-trip на всех плагинах сборки: чтение → запись без правок → сравнение байтов.
- Golden-тесты NIF: чтение → запись → сравнение.
- Сравнение FormID/записей с SkyrimBridge.
- Ручная проверка в игре после каждого этапа (MO2-профиль STB).

## 6. Решения (ответы от 2026-10-10)

| Вопрос | Решение |
|---|---|
| Версии игры | любые: SE 1.5.x, AE 1.6.x/1.7.x, VR, GOG. Ограничения записи (header 1.71, ESL-диапазон) — по версии exe и наличию BEES |
| Распространение | сначала локально, потом open source + Nexus (GPL-3.0) |
| UI | **Dear ImGui (docking) + D3D11** в C# (Hexa.NET.ImGui, Vortice) — один цикл рендера, нет проблем наложения окон на 3D, гизмо и большие списки из коробки |
| Рендер | ближе к игре, с переключением режимов как в CK (освещённый / без света / wireframe / только геометрия) |
| «Меши» | имелся в виду **навмеш** → ручная правка навмеша; NIF-редактор не делаем, NIF только читаем |
| Плагины | один выбранный активный файл, остальные только чтение |
| Сохранение | заменять плагин на месте + бэкап |
| Кодировка | как сейчас: читаем построчно (UTF-8 → cp1251), пишем в преобладающей кодировке плагина |
| Редакторы записей | всё перечисленное; приоритет — то, что взаимодействует с миром (объекты для расстановки) |
| Генерация навмеша | пока не нужна |
| Ландшафт | нужен |
| Квесты/диалоги, facegen | пока нет |
| Связь с игрой | объяснено; решим после этапа 2 |
| Название | STB Editor, репозиторий https://github.com/STB-Team/STB-Editor |
